# ⚙️ Запчасти — складской учёт для магазина

Полноценное приложение для магазина запчастей. Администратор ведёт базу товара, распределяет его по рабочим в разных городах, а рабочие продают запчасти клиентам и ведут учёт.

## 🚀 Быстрый старт

Требуется **Node.js 18+** (для MongoDB Atlas). База данных — **MongoDB** (облачный Atlas, бесплатный тариф M0).

```bash
# 1. Установка зависимостей
npm install

# 2. Заполните .env (см. .env.example): MONGODB_URI, ключи R2 и т.д.

# 3. Первичное наполнение базы (создаёт админа, рабочего и примеры)
npm run seed

# 4. Запуск сервера и клиента вместе
npm run dev
```

Сбросить базу к демо-данным: `npm run seed -- --reset` (или `node server/src/seed.js --reset`).

После запуска:
- **Клиент (интерфейс):** http://localhost:5173
- **Сервер (API):** http://localhost:4000

## ✨ Возможности

### Администратор (контролёр)
- 📥 **Приход товара** — вносит запчасти, пришедшие из Китая, на главный склад.
- 🚚 **Распределение** — отправляет товар конкретным рабочим (в разные города).
- 🔄 **Передача между рабочими** — если у одного нет нужной запчасти, можно перебросить.
- 👥 **Рабочие** — создаёт/редактирует/блокирует аккаунты работников.
- 🗂️ **Категории и запчасти** — полный CRUD каталога.
- 📊 **Дашборд** — остатки на складе, у рабочих, продажи, мало остатков.
- ❌ Администратор **не продаёт** — он только контролирует и распределяет. Продажи оформляют рабочие.

### Рабочий
- 🧰 **Мои запчасти** — видит только свой товар.
- 💰 **Продажи** — оформляет продажу клиенту (остаток уменьшается автоматически).
- ↩️ **Возврат на склад** — отправляет бракованный/непроданный товар обратно (с указанием причины).
- 🔍 **Поиск по всей базе** — находит запчасть и видит, у каких рабочих и на складе она есть.
- 📊 **Личный кабинет** — свои показатели.

## 🔒 Роли и права

| Действие | Админ | Рабочий |
|----------|:-----:|:-------:|
| Создавать/редактировать запчасти | ✅ | — |
| Приход на склад | ✅ | — |
| Распределять по рабочим | ✅ | — |
| Продавать | ❌ | ✅ (только свои) |
| Возвращать на склад | ✅ | ✅ (только свои) |
| Поиск по всей базе | ✅ | ✅ |
| Управлять пользователями | ✅ | — |

Защита от ошибок:
- Нельзя продать/вернуть больше, чем есть в наличии.
- Нельзя удалить запчасть с остатками или историей продаж.
- Нельзя удалить рабочего с остатками.
- Нельзя заблокировать/понизить/удалить самого себя.

## 🖼️ Фото запчастей (Cloudflare R2)

Фото хранятся в облаке Cloudflare R2 и загружаются через форму добавления/редактирования запчасти (только администратор).

**Как настроить:**
1. Создайте bucket в Cloudflare R2 (например `avtozapchasti`).
2. Создайте API-токен с правами **Object Read & Write**.
3. Скопируйте данные в файл `.env` (шаблон — [`.env.example`](.env.example)):
   ```
   R2_ACCOUNT_ID=...
   R2_ACCESS_KEY_ID=...
   R2_SECRET_ACCESS_KEY=...
   R2_BUCKET_NAME=avtozapchasti
   R2_PUBLIC_URL=https://pub-<hash>.r2.dev
   ```
4. Включите **Public Access** в настройках bucket и впишите публичный URL в `R2_PUBLIC_URL`.

Если `.env` не заполнен — фото сохраняются локально в `server/data/uploads/` (fallback для разработки).

Проверить статус: `GET /api/health` → `{"ok":true,"r2":"connected"}` или `"local"`.

## 🔧 Как добавить изменения (расширяемость)

1. **Новое поле в запчасти** — добавьте колонку в [`server/src/db.js`](server/src/db.js), пропишите в INSERT/UPDATE в [`parts.js`](server/src/routes/parts.js) и в форму [`Parts.jsx`](client/src/pages/Parts.jsx).
2. **Новая роль/право** — правило задаётся middleware в [`auth.js`](server/src/auth.js) и `router.use(adminOnly)` в маршрутах.
3. **Новый экран** — добавьте страницу в [`client/src/pages/`](client/src/pages), зарегистрируйте в [`App.jsx`](client/src/App.jsx) и добавьте пункт меню в [`Layout.jsx`](client/src/components/Layout.jsx).
4. **Новый маршрут API** — создайте файл в [`server/src/routes/`](server/src/routes) и подключите в [`index.js`](server/src/index.js).

Данные хранятся в **MongoDB Atlas** (облако). Сбросить базу к чистому состоянию: `npm run seed -- --reset`.

## ☁️ Деплой на Render

Приложение готово к деплою **одним сервисом**: Express раздаёт и API, и собранный фронтенд.

### Быстрый способ — Blueprint

1. Залейте проект на GitHub.
2. На [render.com](https://render.com) → **New** → **Blueprint**.
3. Укажите репозиторий — Render прочитает [`render.yaml`](render.yaml) и создаст сервис автоматически.
4. Заполните секретные переменные: `MONGODB_URI`, `R2_*`, `JWT_SECRET`.

### Ручной способ — Web Service

1. **New** → **Web Service** → подключите репозиторий.
2. Настройки:
   - **Runtime**: Node
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm start`
   - **Plan**: Free
3. Добавьте переменные окружения:

| Ключ | Значение |
|------|----------|
| `MONGODB_URI` | строка подключения MongoDB Atlas |
| `MONGODB_DB` | `zapchast` |
| `JWT_SECRET` | длинная случайная строка |
| `R2_ACCOUNT_ID` | из Cloudflare |
| `R2_ACCESS_KEY_ID` | из Cloudflare |
| `R2_SECRET_ACCESS_KEY` | из Cloudflare |
| `R2_BUCKET_NAME` | `avtozapchasti` |
| `R2_PUBLIC_URL` | `https://pub-...r2.dev` |

4. Нажмите **Deploy**. Через 2-3 минуты приложение доступно по адресу `https://zapchast.onrender.com`.

### После первого деплоя

- Войдите админом (`admin` / `admin123`) и **сразу смените пароль**.
- Привяжите свой домен: Render → Settings → Custom Domain.
